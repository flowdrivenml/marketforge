# Task 11 — Stream-oriented depth persistence

Status: completed; local commit recorded in Git history (subject `task-11: implement stream-oriented depth persistence`). Task10 commit: `292b3f7`.

Implementation: depth uses Task10's stream grouping, ordering, scheduler, filesystem identity and reservation ownership. One ParquetDepthWriter persists compatible sources; each worker invocation constructs an independent decoder, processor, sequence state and boundary tracker. No order-book state transfers across archives. Task completion does not flush/rotate canonical parts. Accepted timestamps, including zero-change events, are checked against declarations and append order.

Metadata: canonical depth and event-index Arrow schemas remain unchanged. Existing event_ordinal remains source-local. The physical zero-based event-index row position is the stream-global output event ordinal. Ordered boundary2 source ranges map that ordinal to task/archive/member provenance and preserve original local ordinals. Canonical row offsets are stream-global. Boundary2 uses `continuity: independent_sources` and retains every full version1 source boundary, together with half-open canonical row and event ranges. Boundaries are serialized incrementally to one file, releasing completed source books. Segment1 retains offsets in its writer's canonical row space; initialization/recovery segments are automatically globally rebased, with source association from ranges. sources.json and manifest3 preserve task contribution spans.

Accounting: existing events_normalized/events_written count canonical levels. Added optional accepted_depth_events to task reports (legacy absent means unknown), incremented only after a successful complete-outcome sink acknowledgment. Finalization verifies each source's accepted-event count separately from canonical levels. It reads the persisted event index, checks offsets/local ordinals/coverage/source spans, and matches every initialization to a reconstruction segment. Required boundary identities and auxiliary files are verified before commit.
