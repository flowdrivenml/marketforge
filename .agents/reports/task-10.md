# Task 10 — Stream-oriented trade persistence

Status: completed; local commit recorded in Git history (subject `task-10: implement stream-oriented trade persistence`).

Implementation: one resource-admitted stream execution unit owns a trade writer through finalization. Both job and global-session entry points use the same unit scheduler. Independent groups run concurrently, sources within a group run sequentially. The reservation is the maximum source estimate, including writer memory, held for the entire unit. These remain admission estimates, not RSS limits.

Grouping: exact logical stream, exchange, canonical instrument ID/symbol/specifications, normalization rules, source-ordering policy, profile identity/fingerprint and feed options. Filesystem directories use SHA256 of serialized compatibility identity, independent of source paths and task completion. Jobs never share units. Compatibility is deliberately conservative across profile revisions.

Ordering: optional prepared `source_time_bounds` carry inclusive timestamps and optional positive partition. Multiple grouped sources require declared order; overlapping windows require explicit ordered distinct partitions within the same window. Touching inclusive windows are allowed. Accepted timestamps must remain in bounds; actual adjacent output must be nondecreasing. No reconciliation, deduplication or timestamp rewriting. Missing/ambiguous order fails explicitly. Existing family resolution expands concrete streams and retains source metadata; it may reread a family archive for separate instruments. Missing family specifications remain unsupported.

Persistence: `streams/<compatibility-sha256>/trades/part-NNNNNN.parquet`; existing encoded-byte trade rotation and row-group targets are preserved. Source completion never flushes/finalizes the shared writer. Manifest protocol 3 adds `streams`, each with logical identity, directory and ordered half-open task row spans. A stream `sources.json` records the completion inventory used during manifest construction. Exact archive/member/profile provenance remains in checksum-protected processing-job.json. Physical files are inventoried once; task counters use successful sink acknowledgments, with final persisted footer totals checked against contributions.

Consumers: discovery reads both layouts; merge manifest resolver accepts v2/v3. Trade inventory intersects each source span with physical parts; cursors retain task-local references and skip unrelated physical rows. Materialization maps task rows to physical offsets and shares row-group registration. Unified merge resolves committed checksum-validated job provenance rather than requiring legacy private jobs. Existing single-stream consumer restrictions remain; multi-instrument normalized datasets are not newly supported by unified merge.

Files: normalize streams/task/executor/session/manifest modules; prepared batch bounds; merge resolver, trade inventory/stream, materialization partition/row index; focused support stream tests and CLI/integrity synthetic input helpers. Existing user fixture and Task12 specification edits were preserved. The pre-existing batch bounds and synthetic PreparedTask initializer are necessary parts of this contract and included; unrelated report/fixture edits excluded.

Verification: historical cargo check passed. 203 library, 162 normalization and 40 benchmark-target tests passed; benchmark cases use synthetic/mock measurements and nonexecuting CLI only. Initial broad support run exposed two synthetic inputs retaining real archive bounds; their input helper now clears those unrelated bounds. Final support run: 38 passed, zero failed. New tests cover shared physical files and canonical timestamps/trade IDs, exact spans, downstream task references, rollover, workers1/3, partial-source failure with independent job success, resource rejection, unsafe logical identifiers, missing order and overlapping declarations. Existing depth remains task-owned and its regression suite passed. Clippy lib/binaries passed with warnings; repository fmt check still reports existing live formatting; changed files formatted separately. No failing correctness checks are accepted.

Limitations: no generalized source reconciliation, asynchronous decode-ahead, or full-family single-pass router. Exact profile compatibility can produce separate physical groups for the same logical stream. Large-workload memory/throughput and macOS runtime unverified. Depth consolidation is Task11. Actual performance benchmarks were not executed; reduced synthetic file counts establish layout only.
