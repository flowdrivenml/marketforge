## F. Remaining contract and coverage limits

- Trade-only conversions use internal reference trades under the Rust contract. An external trade-only reference publication can be selected for a depth or combined source. Observed routes and time ranges cannot establish reference freshness for every event.
- The Rust v4 normalizer selects a compatible profile by canonical identity and the registered feed. An explicit selection pins that compiled interpretation. Family archives still require persisted compatible membership and specification evidence. Unsupported option or base-coin mappings remain blocked by the Engine contract.
- Pipeline runtime overrides are supported for Normalize and Merge. Conversion runtime remains its own configuration family.
- Converted outputs are durably indexed. The current conversion contract does not create a registry publication ID.
- Whole-tree Ruff formatting also reports two pre-existing Forge files outside this scope. The profile generator retains pre-existing formatting outside its edited strings. The terminal coverage above distinguishes actual providers and display modes from simulations.
