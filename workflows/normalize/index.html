Normalize registered data

Turn verified managed raw copies into canonical trade or depth Parquet. Forge selects registered inputs and prepares an Engine batch. A managed run verifies the committed publication and registers its primary files for later inspection or merge.

Select the raw inputs

Use an initialized registry, a verified normalizer and installed profiles for the intended source and content. Start from historical acquisition or register an external recording. Confirm copies are complete with storage inspection. A local file on disk is insufficient for registry-backed selection.

Use a normalization recipe for independent selection or a compatible acquisition recipe, such as the Bybit trades and depth recipe. Choose the venue, instrument or family, content, and interval. For a family, Forge resolves concrete instruments and the applicable specification for each member. A selected archive supplies whole processing input, so the request interval is selection evidence rather than a row filter.

Prepare and check the batch

Replace RECIPE with the saved recipe name or its TOML path. Use the same database environment for preparation, execution, and registration.

mf normalize validate RECIPE
mf --json normalize prepare RECIPE --testing --dry-run
mf --json normalize prepare RECIPE --testing > prepare.json

Validation checks the recipe contract. Dry-run planning resolves registry evidence and reports selection without publishing a batch or validating it with the Engine. Inspect selected archive paths and hashes, nominal coverage gaps, specification provenance, and per-job task and stream counts. Prepare without --dry-run to produce a batch. Continue only when the report is prepared and the Engine is ready.

Run and verify

batch=$(python -c 'import json; print(json.load(open("prepare.json"))["batch_path"])')
mf --json normalize run "$batch" --testing > normalize-result.json

Check for overall completion, verified output, and registered primary files. Use each returned registrations[].catalogue_dataset_id with mf datasets show FILE_ID --testing and mf datasets verify FILE_ID --testing. Read the manifest for source counts, canonical rows, and integrity results. Keep the report and execution intent together so a later investigation can identify the exact submitted batch.

Recover from a failure

Symptom Check
No selected inputs or unexpected gaps Compare recipe scope, interval, archive status, and feed with the storage records.
Missing specification or profile Inspect applicability and source interpretation in the preparation report. Repair the declaration or profile, then prepare again.
Engine failed before commit Read the execution report and Engine diagnostics. Fix the cause before running another attempt.
Output committed but registration failed Use the report’s recovery command with the retained execution intent and original registry.

See the CLI reference for options and exit behavior, the prepared batch contract for generated inputs, and the publication reference for physical output. Continue with dataset inspection or merge.
