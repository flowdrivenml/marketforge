Conversion commands

Generate and submit quote-conversion jobs for verified merge publications. Workflow and prerequisites · Shared CLI behavior

Synopsis and arguments

mf convert new

mf convert new [-h]
                               (--from-merge SOURCE | --from-normalize SOURCE | --from-acquisition SOURCE)
                               --target-quote TARGET_QUOTE [--testing | --production]
                               reference
Argument or option Parser contract
reference Required.
--from-merge Optional.
--from-normalize Optional.
--from-acquisition Optional.
--target-quote Required.
--testing, --production Mutually exclusive. Defaults to production.

mf convert validate

mf convert validate [-h] reference
Argument or option Parser contract
reference Required.

mf convert prepare

mf convert prepare [-h] [--testing | --production] [--dry-run] reference
Argument or option Parser contract
reference Required.
--testing, --production Mutually exclusive. Defaults to production.
--dry-run Default false.

mf convert run

mf convert run [-h] [--testing | --production] [--tui] reference
Argument or option Parser contract
reference Required.
--testing, --production Mutually exclusive. Defaults to production.
--tui Default false.

Command inputs and effects

Action Input and effects Current JSON result
new A new managed name, exactly one upstream selector and an explicit target currency. Reads and fingerprints the upstream TOML. Writes a recipe and refuses an existing destination. Source selectors accept managed names or explicit paths. The parsed --testing flag is optional because creation performs no registry selection status: "template_created", path, and source with the retained declaration
validate Managed recipe name, TOML path, or individual job JSON. A recipe check validates its structure, local constraints and source fingerprint. A job check runs the managed converter’s --validate; install it first. The Forge collection is not a standalone Rust job status: "valid", path, validation, and recipe for TOML
prepare A recipe and the guarded testing registry. Resolves complete registered sources and references, then generates job documents and validates them with the installed converter if available. Dry run performs selection and computes job specifications without invoking the Engine or writing files prepare-report.json shape described below
run Managed recipe, TOML path, retained collection or retained individual job path. A recipe is prepared first. A retained submission reuses its pinned inputs. This action can publish converted data. The documented registry remains unchanged by conversion Run status and execution results with artifact and publication evidence

--tui is an execution option and is mutually exclusive with global --json. An action report with status of blocked, failed, or interrupted returns exit 1. A generated preparation can return exit 0 even when compatibility remains unvalidated. Parse and handled configuration errors use the shared CLI rules.

Preparation result

Read status and compatibility together. blocked identifies failed selection, evidence or metadata and lists blockers. generated identifies a successfully constructed job specification. The CLI uses status: "generated" even when the production parser passes. In that case, compatibility: "validated" records an installed binary that validated every saved job with no remaining compatibility blockers. Otherwise compatibility: "not_validated" retains the exact reasons in compatibility_blockers.

The report identifies requested and effective publication scope, the upstream TOML and digest, source and external reference publications, resolved streams and effective settings. job_path points to the Forge collection or is null on dry run. report_path identifies the saved report when written. In a persisted report jobs[] contains path and sha256, an integer job_id, destination output, selected references, source registry publication ID and string Engine publication ID, and engine_validation of not_run, passed, or failed. Successful validation can include validation_output. The dry-run job records intended_job_path in place of the saved path and digest. artifacts records file pins when persisted.

Compatibility and publication

Current standalone conversion consumes chronological and causal physical merge publications under its validation rules. Matching depth membership does not prevent a configured trade stream from being a reference. Trade-only execution uses internal references. Depth-only requires an external trade-only merge. Combined can bind selected internal trades and supported external references. The policy can consider multiple currency paths within the configured hop limit. It still needs eligible prior observations at event execution.

Instrument metadata is embedded in the prepared job. Forge checks the workspace preparation catalogue against verified historical evidence if the file exists. The Engine does not read a fixed instrument catalogue to run a standalone job. Atomic conversion publication currently requires Linux. Committed converted files can be inspected through Arrow. Conversion registration is unavailable.

mf --json convert prepare NAME --testing --dry-run
mf convert run PATH_TO_CONVERT_JSON --testing
