Normalization profile field index

See the authoring guide for working trade and depth examples. Angle brackets mark a key you supply. Empty brackets mark an array item. An optional key is unset when omitted unless a default is listed. A field marked conditional depends on its enclosing table, target or transform. Applicability labels distinguish trade and depth fields. The compiler and reader check the whole combination.

Identity

Schema discriminator, installed identity and inventory-only marker. Match the venue, instrument and market to the catalogue.

Use the filename <id>.toml under the matching trades/ or depth/ directory. Valid market pairs are spot/spot, perpetual or future with linear or inverse, option/option, and equity/equity. A valid identity does not establish reader support.

Field Type and presence Meaning and constraints
exchange identifier · required · trades, depth Execution venue code, including manual venues. One to 32 lowercase ASCII letters, digits or underscores, starting with a letter. The reserved code external is rejected.
format_code identifier · required · trades, depth Venue and content format identity used by catalogue resolution. Venue uppercase with hyphens in place of underscores. Gate.io uses GATE. Suffix T or B plus a positive decimal integer without leading zero. Must be unambiguous in its venue and market namespace.
id identifier · required · trades, depth Exact installed namespace and filename stem. exchange.instrument_type.market_category.trades|depth Must agree with the three identity keys and installed trades/ or depth/ directory.
instrument_type enum · required · trades, depth Instrument kind matched by the catalogue and task. "spot" — Spot instrument. "perpetual" — Perpetual contract. "future" — Dated future. "option" — Option contract. "equity" — Cash equity.
kind literal · required · trades, depth Document kind. "profile" — Standalone normalization profile.
market_category enum · required · trades, depth Market namespace used for matching. "spot" — Spot instruments. "linear" — Linear perpetuals or futures. "inverse" — Inverse perpetuals or futures. "option" — Options. "equity" — Cash equities.
schema_version literal · required · trades, depth Authoring schema discriminator. 2 — Current self-contained TOML profile.
unsupported_reason string · optional · trades, depth Mark this definition inventory-only with a nonblank reason. Rust checks structure and references but does not enable its processing rules.

Source

Archive wrapper, record representation and source layout.

Read the format and layout rows together. Trades take CSV or JSONL with rows. Depth supports JSONL events and snapshots, specific positional CSV layouts, and a fixed XLSX snapshot layout. Archive members, headers and the selected mappings must match an implemented reader. For XLSX use one header sheet with exactly timestamp, asks and bids, Unix seconds, and common input_ordering = { order = "ascending", sort_by = "timestamp" }.

Field Type and presence Meaning and constraints
source table · required · trades, depth Physical input metadata.
source.archive_day_boundary enum · optional · trades, depth Descriptive calendar boundary for source packaging, independent of event time. "UTC" — UTC boundary. "UTC+8" — UTC plus eight hours.
source.container enum · required · trades, depth Outer wrapper, independent of the inner record representation. "plain" — Uncompressed input. "gzip" — Gzip stream. "zip" — ZIP archive member. "tar_gzip" — Gzip-compressed tar member.
source.daily_packaging literal · optional · trades, depth Descriptive daily package shape. "numbered_zip_chunks" — Numbered ZIP chunks.
source.format enum · required · trades Physical format decoded after opening the wrapper. "csv" — Comma-separated records. "jsonl" — One JSON value per line.
source.format enum · required · depth Physical format decoded after opening the wrapper. "csv" — Comma-separated records. "jsonl" — One JSON value per line. "xlsx" — Excel workbook with the fixed depth layout.
source.granularity enum · required · trades, depth Descriptive archive packaging interval, independent of event frequency. "daily" — Daily package. "hourly" — Hourly package. "monthly" — Monthly package.
source.header boolean · conditional · trades, depth Whether input has a header row. Required for CSV and XLSX. Must be true for XLSX. Forbidden in JSONL trade profiles.
source.maximum_depth_per_side integer · optional · trades, depth Declared maximum levels per side. Positive unsigned 64-bit integer. A bounded_observation must declare the same value in snapshot.levels_per_side.
source.ordering enum · required · trades, depth Declared source ordering. "chronological" — Source-ordered input. "timestamp_sortable" — Input that can be sorted by timestamp. "not_chronological" — Alias for timestamp_sortable.
source.record_format enum · required · trades Logical grouping of records, independent of the physical format. "rows" — Trade rows.
source.record_format enum · required · depth Logical grouping of records, independent of the physical format. "events" — Depth events. "snapshot_rows" — Snapshot rows. "book_rows" — Book rows.
source.trade_id_reset_domain string · conditional · trades Nonblank native identifier reset domain. Required for instrument_scoped and ordered_run. Forbidden for other scopes or when scope is omitted.
source.trade_id_scope enum · optional · trades Native trade identifier uniqueness policy. "global" — Globally unique native ID. "instrument_scoped" — Unique within an instrument and declared reset domain. "ordered_run" — Decimal IDs in one checked, non-reset ordered stream run. "source_local" — Unique only within a source. "unreliable" — ID has no reliable deduplication contract. Trade-only. Requires a native normalization.trade_id.field mapping.
source.workbook_sheets literal · conditional · trades, depth · xlsx Number of worksheets supported by the fixed workbook layout. 1 — Exactly one worksheet. Required for XLSX and forbidden otherwise. XLSX requires header=true, timestamp-sortable input, exactly timestamp/asks/bids, Unix seconds, and ascending timestamp sort.

Fields

Replace with a real source column or JSON path. Use [fields."data.ts"] for a dotted raw key. Omit optional TOML keys to leave them unset unless a default is documented.

In executable mappings, field = "size" references the declared [fields.size] key. For nested JSON use a literal dotted key such as [fields."data.ts"] and field = "data.ts". Where listed, source is a compatibility spelling. Prefer field, and use only field for the event timestamp and trade instrument bindings. CSV positions start at one. Level-array indices start at zero. Precision annotations describe the source and encoding selects the decoder.

Field Type and presence Meaning and constraints
fields table · required · trades, depth Nonempty map of source names to raw field declarations.
fields.<name> table · conditional · trades, depth One literal source column or JSON path. Quote a dotted key in TOML. At least one field is required.
fields.<name>.decode literal · optional · trades, depth Encoding of a structured source field. "json" — JSON-encoded cell or value.
fields.<name>.encoding enum · conditional · trades, depth Timestamp encoding for a mapped source field. "unix_seconds" — Unix epoch seconds. "unix_milliseconds" — Unix epoch milliseconds. "unix_microseconds" — Unix epoch microseconds. "unix_nanoseconds" — Unix epoch nanoseconds. "iso8601_nanoseconds" — ISO 8601 text with nanosecond precision. Required for each effective event_timestamp field. If either timestamp uses ISO 8601, both mapped timestamps must declare ISO 8601 and type string.
fields.<name>.fractional_digits TOML value · optional · trades, depth Descriptive fractional-digit evidence. The compiler does not enforce a digit cap from this key.
fields.<name>.level_fields table · optional · trades, depth Object members for a depth level. Use either positional or object level mappings. A mapping-local level_fields table cannot override a raw field's layout.
fields.<name>.level_fields.order_count string · optional · trades, depth Optional nonempty order count member in the same object level.
fields.<name>.level_fields.price string · conditional · trades, depth Nonempty price member name in an object level. Required when the containing table is used.
fields.<name>.level_fields.quantity string · conditional · trades, depth Nonempty quantity member name in an object level. Required when the containing table is used.
fields.<name>.level_format array of string · optional · trades, depth Positional depth level layout. Array order defines zero-based indices. Exactly ["price", "quantity"] or ["price", "quantity", "order_count"].
fields.<name>.observed_effective_precision TOML value · optional · trades, depth Descriptive observation of effective precision.
fields.<name>.ordering TOML value · optional · trades, depth Descriptive source field ordering. Does not request sorting.
fields.<name>.position integer · optional · trades, depth · csv, xlsx One-based source column position. If used, all positions must be contiguous from one and distinct. Not supported for JSONL trades.
fields.<name>.precision TOML value · optional · trades, depth Descriptive precision evidence. Does not select a timestamp decoder.
fields.<name>.snapshot_precision TOML value · optional · trades, depth Descriptive timestamp precision for snapshots.
fields.<name>.type enum · conditional · trades, depth Declared source field representation. "decimal" — Decimal value. "integer" — Integer value. "string" — Text value. "array" — Array. "boolean" — Boolean value. "integer/string" — Integer or text. "uuid/string" — UUID or text. "integer/bool" — Integer or boolean. "string/integer" — Text or integer. "signed_integer" — Signed integer. "signed_decimal" — Signed decimal. Required when the containing table is used.
fields.<name>.update_precision TOML value · optional · trades, depth Descriptive timestamp precision for updates.
fields.<name>.values TOML value · optional · trades, depth Descriptive observed raw values. A separate mapping defines canonical output.

Normalization

Map raw fields to canonical operations. Use [[normalization.rules]] for multiple targets. Each item inherits common mappings and cannot override a common key.

Use one target or a nonempty [[normalization.rules]] array. Each item has its own target and inherits common mappings without overriding their keys. The tables below show the common paths. Use the same mapping keys within rules where applicable. Keep quantity_encoding, book and the trade instrument binding in common normalization. With depth, use an unsequenced path when both sequence mappings are absent, a consecutive policy with only sequence_start, or a ranged policy with both. All rules in a task must agree. See the bounded-observation exception below.

normalization.book table · optional · depth Depth sequence consistency and descriptive book metadata.
normalization.book.cross_sequence table · optional · depth Descriptive cross-sequence table. It does not establish book continuity.
normalization.book.cross_sequence.field source field reference · optional · depth Source field name used in the book declaration. Its role is defined by the containing declaration.
normalization.book.sequence table · optional · depth Evidence matching the common consecutive-range mapping.
normalization.book.sequence.begin_id table · conditional · depth When supplied, the declaration must match common sequence_start.
normalization.book.sequence.begin_id.field source field reference · optional · depth Source field name used in the book declaration. Its role is defined by the containing declaration.
normalization.book.sequence.continuity_rule literal · conditional · depth Recognized ranged continuity declaration. "next.begin_id = current.begin_id + current.merged_count" — Next range starts after the current range, using the declared count. Required when the containing table is used.
normalization.book.sequence.merged_count table · conditional · depth When supplied, the declaration must match common sequence_count.
normalization.book.sequence.merged_count.field source field reference · optional · depth Source field name used in the book declaration. Its role is defined by the containing declaration.
normalization.book.sequence_id boolean · optional · depth Explicitly record absence of sequence identity. false — No sequence identity.
normalization.book.snapshot_depth descriptive TOML value · optional · depth Descriptive snapshot depth metadata. This key is not a truncation control.
normalization.book.snapshot_depth.asks TOML value · optional · depth Conventional declared ask depth, descriptive.
normalization.book.snapshot_depth.bids TOML value · optional · depth Conventional declared bid depth, descriptive.
normalization.book.snapshot_frequency TOML value · optional · depth Descriptive native snapshot frequency. No enforced unit or timing guarantee.
normalization.book.snapshot_resets_book boolean · optional · depth Assert snapshot reset semantics of the source. true — Assert the source reset convention. The executable snapshot operation comes from the target and snapshot mapping.
normalization.book.update_frequency TOML value · optional · depth Descriptive native update frequency. No enforced unit or timing guarantee.
normalization.book.update_id table or false · optional · depth Declare the update identifier, or set this key to false to record its absence. A table must equal the common sequence_start mapping.
normalization.book.update_id.field source field reference · optional · depth Source field name used in the book declaration. Its role is defined by the containing declaration.
normalization.sequence_count table · optional · depth Count covered by a source range. Requires sequence_start. Forbidden for bounded observations.
normalization.sequence_count.field source field reference · conditional · depth Name of a declared raw column or JSON path. Required when this mapping is used. The source alias is accepted.
normalization.sequence_count.source source field reference · optional · depth Direct source-field spelling accepted by the compiled rule parser. Prefer field in authored profiles.
normalization.sequence_start table · optional · depth Source sequence or update identifier. Without sequence_count this does not establish ranged continuity.
normalization.sequence_start.field source field reference · conditional · depth Name of a declared raw column or JSON path. Required when this mapping is used. The source alias is accepted.
normalization.sequence_start.source source field reference · optional · depth Direct source-field spelling accepted by the compiled rule parser. Prefer field in authored profiles.

Feeds

Gate.io depth can declare snapshot and incremental feed variants. Replace with one of those keys. Each feed supplies its own source, fields and normalization.

Each variant has its own complete depth Source, Fields and Normalization tables. Keep the complete top-level definition as well. Set feed = "snapshot" or feed = "incremental" in acquisition request source options.

Field Type and presence Meaning and constraints
feeds table · optional · depth Optional Gate.io depth feed map. Default {}.
feeds.<feed> table · optional · depth Complete feed override with its own source, fields and normalization. Only snapshot and incremental feed keys are supported. Only Gate.io depth.
feeds.<feed>.fields table · conditional · depth Complete raw field definitions for this variant. Required when the containing table is used.
feeds.<feed>.normalization table · conditional · depth Complete depth operations for this variant. Required when the containing table is used.
feeds.<feed>.source table · conditional · depth Complete physical metadata for this variant. Required when the containing table is used.
