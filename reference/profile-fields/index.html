Normalization profile field index

Browse schema 2 without loading profiles or opening a database. A name in angle brackets is a map key. Empty brackets identify an array item. Each TOML example is a fragment of a profile.

Use the profile reference to look up interpretation and see complete examples. The Rust Engine checks the effective rules and catalogue compatibility.

Identity

Schema discriminator, installed identity and inventory-only marker.

exchange

string · required · trades, depth · csv, jsonl, xlsx

Execution venue code, including manual venues.

  • One to 32 lowercase ASCII letters, digits or underscores, starting with a letter. The reserved code external is rejected.
exchange = "bybit"

format_code

string · required · trades, depth · csv, jsonl, xlsx

Venue and content format identity used by catalogue resolution.

  • Venue uppercase with hyphens in place of underscores. Gate.io uses GATE.
  • Suffix T or B plus a positive decimal integer without leading zero. Must be unambiguous in its venue and market namespace.
format_code = "BYBIT-T2"

id

string · required · trades, depth · csv, jsonl, xlsx

Exact installed namespace and filename stem.

  • exchange.instrument_type.market_category.trades|depth
  • Must agree with the three identity keys and installed trades/ or depth/ directory.

Related fields exchange, instrument_type, market_category.

id = "bybit.perpetual.linear.trades"

instrument_type

string · required · trades, depth · csv, jsonl, xlsx

Instrument kind matched by the catalogue and task.

  • "spot" — Spot instrument.
  • "perpetual" — Perpetual contract.
  • "future" — Dated future.
  • "option" — Option contract.
  • "equity" — Cash equity.
instrument_type = "perpetual"

kind

string · required · trades, depth · csv, jsonl, xlsx

Document kind.

  • "profile" — Standalone normalization profile.
kind = "profile"

market_category

string · required · trades, depth · csv, jsonl, xlsx

Market namespace used for matching.

  • "spot" — Spot instruments.
  • "linear" — Linear perpetuals or futures.
  • "inverse" — Inverse perpetuals or futures.
  • "option" — Options.
  • "equity" — Cash equities.

Related fields instrument_type.

market_category = "linear"

schema_version

integer · required · trades, depth · csv, jsonl, xlsx

Authoring schema discriminator.

  • 2 — Current self-contained TOML profile.
schema_version = 2

unsupported_reason

string · optional · trades, depth · csv, jsonl, xlsx

Mark this definition inventory-only with a nonblank reason. Rust checks structure and references but does not enable its processing rules.

unsupported_reason = "Reader not implemented"

Source

Archive wrapper, record representation and source layout.

source

table · required · trades, depth · csv, jsonl, xlsx

Physical input metadata.

[source]

source.archive_day_boundary

string · optional · trades, depth · csv, jsonl, xlsx

Declared day boundary of source packaging.

  • "UTC" — UTC boundary.
  • "UTC+8" — UTC plus eight hours.
archive_day_boundary = "UTC+8"

source.container

string · required · trades, depth · csv, jsonl, xlsx

Outer wrapper, independent of the inner record representation.

  • "plain" — Uncompressed input.
  • "gzip" — Gzip stream.
  • "zip" — ZIP archive member.
  • "tar_gzip" — Gzip-compressed tar member.
container = "zip"

source.daily_packaging

string · optional · trades, depth · csv, jsonl, xlsx

Optional daily package shape.

  • "numbered_zip_chunks" — Numbered ZIP chunks.
daily_packaging = "numbered_zip_chunks"

source.format

string · required · trades · csv, jsonl

Inner decoder format. Trade inputs use CSV or JSONL.

  • "csv" — Comma-separated records.
  • "jsonl" — One JSON value per line.
format = "jsonl"

string · required · depth · csv, jsonl, xlsx

Inner decoder format. Trade inputs use CSV or JSONL.

  • "csv" — Comma-separated records.
  • "jsonl" — One JSON value per line.
  • "xlsx" — Excel workbook with the fixed depth layout.
format = "jsonl"

source.granularity

string · required · trades, depth · csv, jsonl, xlsx

Archive packaging interval declaration.

  • "daily" — Daily package.
  • "hourly" — Hourly package.
  • "monthly" — Monthly package.
granularity = "daily"

source.header

boolean · conditional · trades, depth · csv, jsonl, xlsx

Whether input has a header row.

  • Required for CSV and XLSX. Must be true for XLSX. Forbidden in JSONL trade profiles.
header = true

source.maximum_depth_per_side

integer · optional · trades, depth · csv, jsonl, xlsx

Declared maximum levels per side.

  • Positive unsigned 64-bit integer.
  • A bounded_observation must declare the same value in snapshot.levels_per_side.
maximum_depth_per_side = 10

source.ordering

string · required · trades, depth · csv, jsonl, xlsx

Declared source ordering.

  • "chronological" — Source-ordered input.
  • "timestamp_sortable" — Input that can be sorted by timestamp.
  • "not_chronological" — Alias for timestamp_sortable.
ordering = "chronological"

source.record_format

string · required · trades · csv, jsonl

Logical record layout. Only rows is accepted for trades.

  • "rows" — Trade rows.
record_format = "events"

string · required · depth · csv, jsonl, xlsx

Logical record layout. Only rows is accepted for trades.

  • "events" — Depth events.
  • "snapshot_rows" — Snapshot rows.
  • "book_rows" — Book rows.
record_format = "events"

source.trade_id_reset_domain

string · conditional · trades · csv, jsonl

Nonblank native identifier reset domain.

  • Required for instrument_scoped and ordered_run. Forbidden for other scopes or when scope is omitted.
trade_id_reset_domain = "session"

source.trade_id_scope

string · optional · trades · csv, jsonl

Native trade identifier uniqueness policy.

  • "global" — Globally unique native ID.
  • "instrument_scoped" — Unique within an instrument and declared reset domain.
  • "ordered_run" — Decimal IDs in one checked, non-reset ordered stream run.
  • "source_local" — Unique only within a source.
  • "unreliable" — ID has no reliable deduplication contract.
  • Trade-only. Requires a native normalization.trade_id.field mapping.

Related fields source.trade_id_reset_domain, normalization.trade_id.field.

trade_id_scope = "source_local"

source.workbook_sheets

integer · conditional · trades, depth · xlsx

Number of worksheets supported by the fixed workbook layout.

  • 1 — Exactly one worksheet.
  • Required for XLSX and forbidden otherwise. XLSX requires header=true, timestamp-sortable input, exactly timestamp/asks/bids, Unix seconds, and ascending timestamp sort.
workbook_sheets = 1

Fields

Named raw columns or literal JSON paths, with decoding and descriptive metadata.

fields

table · required · trades, depth · csv, jsonl, xlsx

Nonempty map of source names to raw field declarations.

[fields.timestamp]

fields.<name>

table · conditional · trades, depth · csv, jsonl, xlsx

One literal source column or JSON path. Quote a dotted key in TOML.

  • At least one field is required.
[fields."data.ts"]

fields.<name>.decode

string · optional · trades, depth · csv, jsonl, xlsx

Encoding of a structured source field.

  • "json" — JSON-encoded cell or value.
decode = "json"

fields.<name>.encoding

string · conditional · trades, depth · csv, jsonl, xlsx

Timestamp encoding for a mapped source field.

  • "unix_seconds" — Unix epoch seconds.
  • "unix_milliseconds" — Unix epoch milliseconds.
  • "unix_microseconds" — Unix epoch microseconds.
  • "unix_nanoseconds" — Unix epoch nanoseconds.
  • "iso8601_nanoseconds" — ISO 8601 text with nanosecond precision.
  • Required for each effective event_timestamp field. If either timestamp uses ISO 8601, both mapped timestamps must declare ISO 8601 and type string.

Related fields normalization.event_timestamp.field, normalization.system_timestamp.field.

encoding = "unix_milliseconds"

fields.<name>.fractional_digits

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive fractional-digit evidence. The compiler does not enforce a digit cap from this key.

fractional_digits = 6

fields.<name>.level_fields

table · optional · trades, depth · csv, jsonl, xlsx

Object members for a depth level.

  • Use either positional or object level mappings. A mapping-local level_fields table cannot override a raw field's layout.
level_fields = { price = "p", quantity = "q" }

fields.<name>.level_fields.order_count

string · optional · trades, depth · csv, jsonl, xlsx

Optional nonempty order count member in the same object level.

order_count = "n"

fields.<name>.level_fields.price

string · required · trades, depth · csv, jsonl, xlsx

Nonempty price member name in an object level.

price = "p"

fields.<name>.level_fields.quantity

string · required · trades, depth · csv, jsonl, xlsx

Nonempty quantity member name in an object level.

quantity = "q"

fields.<name>.level_format

array of string · optional · trades, depth · csv, jsonl, xlsx

Positional depth level layout. Array order defines zero-based indices.

  • Exactly ["price", "quantity"] or ["price", "quantity", "order_count"].

Related fields fields.<name>.level_fields.

level_format = ["price", "quantity"]

fields.<name>.observed_effective_precision

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive observation of effective precision.

observed_effective_precision = "second"

fields.<name>.ordering

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive source field ordering. Does not request sorting.

ordering = "price_descending"

fields.<name>.position

integer · optional · trades, depth · csv, xlsx

One-based source column position.

  • If used, all positions must be contiguous from one and distinct. Not supported for JSONL trades.
position = 1

fields.<name>.precision

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive precision evidence. Does not select a timestamp decoder.

precision = "millisecond"

fields.<name>.snapshot_precision

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive timestamp precision for snapshots.

snapshot_precision = "second"

fields.<name>.type

string · required · trades, depth · csv, jsonl, xlsx

Declared source field representation.

  • "decimal" — Decimal value.
  • "integer" — Integer value.
  • "string" — Text value.
  • "array" — Array.
  • "boolean" — Boolean value.
  • "integer/string" — Integer or text.
  • "uuid/string" — UUID or text.
  • "integer/bool" — Integer or boolean.
  • "string/integer" — Text or integer.
  • "signed_integer" — Signed integer.
  • "signed_decimal" — Signed decimal.
type = "decimal"

fields.<name>.update_precision

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive timestamp precision for updates.

update_precision = "100ms"

fields.<name>.values

TOML value · optional · trades, depth · csv, jsonl, xlsx

Descriptive observed raw values. A separate mapping defines canonical output.

values = ["snapshot", "delta"]

Normalization

Effective trade or depth operations and source-to-canonical mappings.

In an array of rules, each item has a required target and can supply the matching trade or depth mappings listed here. Use normalization.rules[].target or substitute normalization.rules[] for normalization in a mapping path. Common-only settings are quantity_encoding and book, plus the trade instrument binding.

normalization

table · required · trades, depth · csv, jsonl, xlsx

Common mappings and operation selection.

[normalization]

normalization.asks

table · conditional · depth · csv, jsonl, xlsx

Ask-array mapping.

  • Requires bids. Mutually exclusive with scalar price, quantity and side.
asks = { field = "asks" }

normalization.asks.decode

string · optional · depth · csv, jsonl, xlsx

Optional level-array decoding.

  • "json" — Decode a JSON-encoded level collection.
decode = "json"

normalization.asks.field

string · conditional · depth · csv, jsonl, xlsx

Declared raw bid or ask collection.

field = "data.b"

normalization.asks.level_fields

table · optional · depth · csv, jsonl, xlsx

Mapping-local alternative to positional or raw-field object layout.

  • Requires field. Cannot override level_format or level_fields in the raw declaration.
level_fields = { price = "p", quantity = "s" }

normalization.asks.level_fields.order_count

string · optional · depth · csv, jsonl, xlsx

Optional nonempty order count member in the same object level.

order_count = "n"

normalization.asks.level_fields.price

string · required · depth · csv, jsonl, xlsx

Nonempty price member name in an object level.

price = "p"

normalization.asks.level_fields.quantity

string · required · depth · csv, jsonl, xlsx

Nonempty quantity member name in an object level.

quantity = "q"

normalization.asks.order_count_field

string · optional · depth · csv, jsonl, xlsx

Optional nonempty order count member for object levels.

  • Requires object price and quantity members.
order_count_field = "count"

normalization.asks.order_count_index

integer · optional · depth · csv, jsonl, xlsx

Optional unsigned zero-based order count position for positional levels.

  • Not compatible with object price and quantity members.
order_count_index = 2

normalization.asks.price_field
